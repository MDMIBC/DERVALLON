# Custom-order wizard — frontend preview specification

**Status:** Review-only UI. The existing Design Studio remains unchanged; this is a separate, discoverable route.

## Objective and assumptions

DREVALLON visitors can explore an illustrative suit configuration through **Fabric → Style → Measurements → Review**. The page is an interface prototype, not a product, fit, stock, price or manufacturer integration. Fabric/color studies and style labels are illustrative, not inventory claims. Measurements are entered in centimetres; the field list is provisional until a tailor/manufacturer approves it. The user may leave measurements blank. Nothing is saved by default; an explicit **Save for Later** action may store only choices and measurements on this browser for up to seven days. Nothing is transmitted, tracked, copied to the clipboard, or added to a URL. Reloading or leaving without saving clears the in-memory form.

## Experience contract

The entry point lives in the current Design Studio introduction; homepage and existing Studio navigation remain intact. Fabric selection uses four visibly different swatches with named radio-style choices. Style selection requires a silhouette and lapel; every choice has an explicit selected state and remains editable. A native progress meter and adjacent visible text show the current step and steps remaining. Optional photo references can be selected during Style or Measurements, with three previews maximum; accepted types are JPEG, PNG, WebP and AVIF at up to 5 MB per image. Invalid selections are rejected as a group. Previews use in-tab object URLs that are revoked on removal, reset and unmount: photos are **not uploaded or persisted**. Measurement inputs have visible labels, short measuring descriptions, expandable keyboard-operable guidance with simplified diagrams, and a shared unit. The diagrams are orientation aids, not a certified tailoring protocol. Only nonempty values are checked for finite numbers greater than zero and no more than 300 cm. Inline errors identify invalid fields, focus moves to the first invalid field on Continue, and Back retains values in memory. Step changes announce the new stage and move focus to its heading. Review summarizes all choices and local photo references; **Complete preview** shows an explicit **No order was placed or sent** state with a Start again control. There is no endpoint call, backend write, authentication, payment, live price, checkout or submission.

The layout extends the existing ivory, navy and brass design language, uses the existing serif/sans pairing, real campaign-reference imagery only as labelled decoration, and uses CSS-only conceptual swatch textures rather than unapproved physical fabric photos. Desktop shows step content with a live navy summary; mobile stacks the summary under the steps. All controls use native buttons, inputs and fieldsets, with visible focus, text labels and reduced-motion-safe transitions.

## Technical structure and commands

The new page is `client/src/pages/CustomOrderPage.tsx`, lazy-loaded through `client/src/App.tsx`. Its isolated styles are in `client/src/pages/custom-order.css`; data and pure validation live in `client/src/lib/orderPreview.ts`. No changes to `server/`, database, secrets, analytics or the persistent draft key used by the existing Design Studio. Use `pnpm exec vitest run` for tests, `pnpm check` for TypeScript and `pnpm build` for the production bundle. Browser QA covers normal progression, invalid measurement recovery, step backtracking, review completion, small-phone layout, theme/readability and keyboard access.

## Boundaries

**Always:** Label sample fabrics; store measurements only after explicit Save for Later; keep photos memory-only; maintain input units, focus and error states; verify no network submission. **Ask before future implementation:** real fabric catalogue/stock/pricing, production measurement definitions, account persistence, personally identifying contact fields, consent/retention text, or manufacturer forwarding. **Never in this preview:** pretend an order was placed, silently persist form changes, store photos in localStorage/sessionStorage, expose API credentials, or use the existing illustrative Studio save button as an order-confirmation action.

## Final-review and reference-editor extension

The current **Review** stage is already fourth and final: do not add a redundant fifth step. Expand it to display the selected fabric and style, **all six** measurement values (including explicit “Not supplied” states), and the final adjusted reference thumbnails. Each section offers an Edit link back to its step. Require an unchecked-by-default acknowledgement that the visitor has double-checked the choices and understands that **Confirm preview is not an order**. Changing anything after entering Review clears the acknowledgement; confirmation cannot proceed while a required choice or entered measurement is invalid. The completion state remains local-only and clearly states that nothing was sent.

Reference photos gain an **in-page, non-destructive** editor opened from each thumbnail in Style or Measurements. Controls: rotate by 90° in either direction; crop to original aspect, square or 4:5 portrait; adjust zoom and horizontal/vertical focal position. The canvas preview is the actual crop. Applying produces a new browser-local preview URL, retaining the uploaded original for future edits; Cancel changes nothing. Edited URLs are revoked on replacement, removal, restart and unmount. Cap the export's long edge, handle decode/export failure without losing the original, and retain the three-file/5 MB input limits. This does **not** upload a file or transmit any measurement.

The stock-reference Shirt and Tie photos are **not approved campaign photography**. No new owner-approved photographs accompanied this request, and image-search results cannot establish owner approval. Keep the current references marked as such until the owner supplies approved source files or explicit documented asset approvals. At that time, create optimized variants and update category, product, alt-text and register paths together. Do not remove the reference label or claim launch readiness before then.

## Opt-in local draft and tailor-help extension

Save for Later stores a namespaced, versioned JSON draft containing **fabric, silhouette, lapel and optional centimetre measurements only**, plus a seven-day expiry; **never** photo bytes, blob URLs, confirmation acknowledgement, contact details, or server identifiers. A visitor can restore or discard an unexpired saved draft on returning; do not auto-restore without an explicit click. Validate structure and field values before restoring, delete invalid/expired data, gracefully handle disabled/full storage, and remove an existing draft on preview confirmation or Start again. Saving must not override unfinished in-memory choices unless the visitor explicitly restores. Warn that browser storage is not encrypted and other people using the same device/browser may see measurements. Not a real client profile; no backend sync. The final review gets a keyboard-accessible **Need help?** disclosure beside Confirm preview, offering the site's measurement-enquiry route while plainly stating that the current Contact form is a local demonstration and **does not deliver a request to a tailor**. A real tailor inbox needs owner-approved contact details and delivery wiring.
